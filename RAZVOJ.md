# Развој и одржавање

Кратак водич за свакога ко буде мењао ову апликацију — укључујући будућег себе.

## Шта је ово

Вежбаоница за теоријски испит **А категорије** над званичном базом питања (еУправа).
Нема сервера, нема базе података, нема билд корака за саму апликацију: то је обичан
HTML + CSS + један JS фајл. Напредак се чува у `localStorage` прегледача.

## Покретање

| Начин | Како | Напомена |
|---|---|---|
| Најпростије | двоклик на `index.html` | ради директно из фолдера (`file://` режим) |
| Ако нешто заглави | двоклик на `Pokreni.bat` | диже локални сервер на порту 8137 и отвара прегледач |
| Ручно | `node serve.mjs` па `http://localhost:8137` | исто као горе |

**Адресе и историја од v146:** hash адресе (`#/sek/c30`, `#/p/7921`) и
стрелице прегледача раде преко сервера и у `file://` режиму. History API памти
појединачне посете; када није доступан, остаје обично hash рутирање. То не
уклања остала ограничења `file://`, попут service worker-а и заједничке браве.

Локални сервер служи само јавне фајлове апликације и `img/<број>.jpg`.
Извози напретка, `tools/`, `.git/` и остали фајлови нису доступни преко HTTP-а.
Када се додаје јавни ресурс, допунити листу у `serve.mjs` и њену проверу.

**Јавни описи од v147:** `STR` у `app.js`, метаподаци `index.html`, плакат и
README морају описивати исте стварне услове. Не представљати незванична
објашњења као потпуно проверена, посматрани распоред извлачења као гаранцију,
инсталацију као гаранцију очувања напретка или offline као доступност слика
које још нису преузете. Подаци напретка су локални; GoatCounter и остали
спољни захтеви описани су засебно у README-у.

## Структура

```
index.html          костур странице (све „екране" држи као <section class="view">)
app.js              цела апликација (један IIFE, без зависности)
style.css           стилови, укључујући тамну тему (body.dark) и широке екране (≥1200px)
data.js             ГЕНЕРИСАНО — питања, области, подобласти
image-baseline.js   ЗАМРЗНУТО — отисци старих слика за већ отворене табове
explanations.js     ГЕНЕРИСАНО — објашњења по питању + картице појмовника
version.js          број верзије (за обавештење „стигла нова верзија")
img/                слике питања (704 комада)
serve.mjs           мали статички сервер за локални развој
tools/              алати за освежавање података (види доле)
tools/arhiva/       примењене једнократне закрпе — историја, не покретати поново
```

### Екрани

Сваки екран је `<section id="view-XXX" class="view">`. Приказује се додавањем
класе `active` (`show('browse')` у `app.js`).

> **Замка:** ако у CSS-у пишеш `#view-home { display: … }`, то ће надјачати
> `.view { display: none }` и екран ће остати видљив преко свега. Увек пиши
> `#view-home.active { display: … }`. Провера:
> ```bash
> grep -oE '#view-[a-z]+\s*\{[^}]*display:' style.css | grep -v '\.active'
> ```
> (излаз мора бити празан)

## Ток података

```
еУправа API ──harvest.mjs──> tools/base-A.json ──build-data.mjs──> data.js
                                    │
                                    └──download-images.mjs──> img/

ручно писани текстови у tools/build-explanations.mjs ──build-explanations.mjs──> explanations.js
```

`practiceId` служи само за захтеве при преузимању: `harvest.mjs` га не уписује
у јавни JSON. Не додавати личне идентификаторе, приступне податке или извозе
напретка у репозиторијум. Чишћење текућег фајла не брише старе Git ревизије.

Провере јавних фајлова и санитаризације (синтетички подаци, без портала/Chrome-а):

```bash
node --test tools/tests/source-privacy.test.mjs tools/tests/server-public-files.test.mjs
```

### Алати (`tools/`)

| Алат | Чему служи |
|---|---|
| `harvest.mjs <guid> <lang> <out>` | преузима базу питања са еУправе (треба важећи GUID за вежбање) |
| `build-data.mjs [--lat фајл] [--cyr фајл] [--images фасцикла] [--out фајл] [--date YYYY-MM-DD]` | спаја проверена два писма у `data.js` |
| `download-images.mjs --guid GUID [--source base.json] [--out img] [--refresh]` | преузима слике питања; подразумевано `tools/base-A.json` → `img/` |
| `build-explanations.mjs` | од извора у самом фајлу прави `explanations.js` |
| `bump-version.mjs` | подиже број верзије и ознаке у `index.html` |
| `patch-srpski.mjs` | једнократна језичка исправка (задржано ради историје) |

`harvest.mjs` најпре преузима и проверава цео скуп одговора, па тек онда
замењује излаз. Један неуспео захтев, неважећи JSON, поновљени ID, погрешан
број одговора или неслагање са изричитим API бројачем заустављају замену.
Ваљане празне подобласти остају дозвољене. Сваки захтев има највише три
покушаја по 30 секунди; приватни GUID се не исписује и не улази у извор.
Подразумевано пише `base.json` у радној фасцикли, језик 15; језик 9 је ћирилица.
Без очекиваног броја из API-ја не може се доказати да је сервер послао баш сва
питања: унутрашња сагласност није доказ потпуности портала. Не уписивати 1.327
као универзални број будућих верзија базе. Провера без портала:
`node --test tools/tests/harvest-integrity.test.mjs tools/tests/source-privacy.test.mjs`.

`build-data.mjs` проверава оба извора истим валидатором, а затим њихову
међусобну сагласност: ID-јеве, области/подобласти, бодове, тачне изборе,
обавезан број одговора, ознаке слика и непразне текстове на оба писма.
Потребне слике морају постојати као непразни фајлови; то није провера њиховог
значења. Од v157 builder израчунава њихове SHA-256 отиске у `imageHashes`.
Све провере претходе припреми/замени излаза. Подразумеване путање
припадају пројекту, експлицитне радној фасцикли. `--date` даје поновљив датум
генерисања; без њега узима се дан изградње у UTC-у. То **није** датум провере
портала или прописа. Провера: `node --test tools/tests/build-data.test.mjs`.

Затечена разлика при обнови v139 из сирових извора: 1.112 питања има другачији
редослед понуђених одговора од праћеног `data.js`, уз исте ID-јеве и вредности.
То је постојало и са старим алатом. Builder задржава редослед латиничног извора;
не зависити од старог излаза ради прикривања разлике. При следећој стварној обнови
базе посебно прегледати diff и поновити испит/историју. Исправка алата није
регенерисала питања. Миграција v157 додала је само мапу отисака у постојећи
јавни излаз, чувајући дословно сва остала поља и редоследе.

Уредничка исправка v173 упарила је 37 ћириличних вредности у `data.js` са
45 вредности у `tools/base-A-cyr.json` (осам су поновљени називи подобласти).
Исправљена су помешана слова и дословни кодови N/T/TWI, уз тачну проверу
стабилних ID-јева и непромењених осталих бајтова. Пуна регенерација није
коришћена да мала словна исправка не би успут променила редоследе одговора.
Доказ и граница провере: `docs/revizija-sadrzaja/grupe/021-ispravke-pisma.md`.

Путање алата за слике без аргумената везане су за пројекат; експлицитне путање
су релативне радној фасцикли. Извор се у целини проверава пре мреже и уписа.
Већ преузета слика са исправним JPEG почетком/крајем прескаче се, осим уз
`--refresh`. Нови фајл се прво припрема поред одредишта, па тек онда замењује
стари. HTTP грешка, HTML или прекинут JPEG остављају стару слику и дају
неуспешан излазни код; GUID се не исписује. Ово није провера значења или
потпуно декодирање слике. Пре јавне објаве замењених слика поново направити
`data.js`, прегледати diff, освежити садржајну евиденцију и подићи број издања.
`verify.mjs` одбија мапу која не одговара стварним бајтовима. Не мењати ручно
кључ кеша или историјски `image-baseline.js` при обичној обнови слика.
Провера без портала: `node --test tools/tests/download-images.test.mjs`.

**После сваке измене** `app.js`/`style.css`/`index.html` покрени:

```bash
cd tools && node bump-version.mjs
```

Алтернативно, из корена: `node tools/bump-version.mjs`. Путање се рачунају
према скрипти. Пре уписа проверавају се оба фајла и свих пет ознака; неисправан
улаз их оставља нетакнутим. Нови садржаји се најпре припремају у привременим
фајловима. Замена два фајла није једна трансакција: после прекида између замена
вратити усклађен пар `version.js`/`index.html` из истог commit-а па поновити.
Провера: `node --test tools/tests/bump-version.test.mjs`.

Тиме се мења `version.js` и `?v=` ознаке у `index.html`, па прегледач узима нове
фајлове, а отворени табови добијају траку „Стигла је нова верзија".

## Конвенције

### Једна локална команда и GitHub провере

Из корена пројекта: `node tools/verify.mjs` (Node.js 22 или новији).
Иста скрипта ради и ако се позове пуном путањом из друге фасцикле. Проверава
верзионисане ресурсе, синтаксу активних скрипти, све `tools/tests/*.test.mjs`
и актуелност евиденције садржаја. Не покреће генераторе/архивиране закрпе,
не отвара Chrome, не приступа порталу и не мења број апликације. Тестови
користе привремене синтетичке пројекте и локалне сервере.

`.github/workflows/verify.yml` покреће исту команду на Linux-у и Windows-у
за push/PR. Actions су везане за конкретне commit-е; дозвола је само читање
репозиторијума. Workflow нема објављивање сајта. Пад зауставља проверу, а
пролаз **не значи** да су browser токови или сва питања семантички проверени.
Њихове засебне команде и ограничења су у одељку провера испод.

### Двојно писмо (латиница + ћирилица)

Сваки текст видљив кориснику постоји као пар `{ l: 'latinica', c: 'ћирилица' }`.
У `app.js` то су уноси у објекту `STR`, а испис иде кроз `L('kljuc')`.

Објашњења се **не пишу двапут**: у `build-explanations.mjs` пише се само латиница,
а ћирилица се добија аутоматским пресловљавањем при билду. Пресловљавач чува
ознаке које морају остати латиничне (`km/h`, `kW`, `cm³`, `mg/ml`, `kg`, категорије
`AM`/`A1`/`A2`/`A`/`B`, натписи на знаковима `STOP`, `BUS`).

> **Провера после билда:** излаз мора бити празан.
> ```bash
> node -e "const s=require('fs').readFileSync('explanations.js','utf8');console.log((s.match(/[A-Za-zčćžšđ][Ѐ-ӿ]|[Ѐ-ӿ][a-zčćžšđ]/g)||[]).filter(t=>!/^n/.test(t)))"
> ```

### Уређивање `tools/build-explanations.mjs`

Фајл садржи **NUL бајтове** (користе се као граничници при пресловљавању), па
уобичајени алати за уређивање знају да га оштете. Мењај га **скриптом** која ради
`split`/`join` над тачним низом и гласно пада ако низ није нађен тачно једном —
образац видљив у `tools/arhiva/`.

### Провера садржаја (научено на грешкама)

Садржајни налази се сада воде по ID-ју у
[евиденцији ревизије](docs/revizija-sadrzaja/METODOLOGIJA.md).
[Група 002](docs/revizija-sadrzaja/grupe/002-prvenstvo-i-brzine.md) показује
поступак за измену заједничке картице: она поново отвара зависна питања,
али им не додељује одобрење. Новији пропис провери и када званични PDF на
сајту министарства касни: за сигнализацију је било потребно допунити текст
кроз 2021. консолидацијама 2024. и 2026. и изворним изменама PIS-а.

[Група 004](docs/revizija-sadrzaja/grupe/004-brzine-potpun-pregled-kartice.md)
бележи потпун преглед картице брзина и свих 15 зависних питања. Посебна CLI
провера `tools/tests/brzine-card.browser.js` мери боје знакова, контраст,
два писма и стварно заклањање цртежа навигацијом. Покреће се само на
изолованом localhost-у и прави нове контексте. Њених 200% односи се на
основни текст странице; натписи SVG-а имају сопствену величину. Успешна
геометријска провера не потврђује смисао осталих картица.

**Плакат од v149:** `plakat.html` има засебан print распоред за једну A4
страну са маргинама 14 mm. После измене текста проверити стварни PDF,
комплетно подножје и QR, уз искључена заглавља/подножја прегледача.
Снимак екрана није доказ броја одштампаних страна.

**Дуге адресе од v152:** линкови у `.trustList` користе `overflow-wrap:
anywhere` и `var(--blue)`. Провера `mobile-layout.browser.js` отвара FAQ на
320px са текстом од 30px, мери ширину документа и контраст нормалног/hover
линка, и проверава да су оригинална адреса, текст и подвлачење очувани.
Навигациони селектори обухватају и дугмад и стварне линкове. Сценарио без
ResizeObserver-а мора имати свој нови BrowserContext због једног писца.

Сваку **визуелну** тврдњу (боја, облик, положај руке на знаку) провери **отварањем саме слике**
`img/<qId>.jpg` — текстуална провера не хвата грешке у бојама. Тако је нађено да је картица
tврдила да је почетак аутопута плава табла, а он је **зелен** (слике 9155/9083).

### Објашњења

- Свако објашњење креће од **тачног одговора баш тог питања**, па објашњава зашто.
- Замке (примамљиви нетачни одговори) се именују и разрешавају.
- Чланови закона се наводе **само после дословне провере** у тексту закона.
- Казнене мере: **без динарских износа** (мењају се изменама закона) — уче се класе.
- Где се званични одговор разилази са важећим законом, текст то каже поштено
   („у испитној бази…"), без измишљања.

## Симулација испита

`SIM_SLOTS` у `app.js` описује шаблон правог испита изведен из **пет званичних
извлачења** (данас их је шест): 41 питање, 98 поена, 45 минута, праг 84 поена (85%).
Распоред по областима је фиксан (нпр. Правила 19 питања/46 поена, Сигнализација
13/34, Последице 0), а питања се бирају насумично унутар сваке ћелије.

Симулација је намерно **верна испиту** — без помоћи којих на испиту нема
(нема објашњења док траје, нема мреже питања, увек светла тема).

## Провера пре објављивања измене

**Историја симулација (v130):** ID изабраног одговора проверава се међу
одговорима тог питања, не међу ID-јевима питања. Збир и преглед по областима
проверавају се на сагласност; ако стари детаљи не одговарају сачуваном резултату,
приказује се објашњење и сачувана листа погрешних питања. Раније избрисане
изборе није могуће реконструисати. Празан стари избор зато не доказује да
кандидат није одговорио. Провера: `node --test tools/tests/simulation-history.test.mjs`.

За сваку измену која дира УЧЕЊЕ, РЕД ПОНАВЉАЊА или СИМУЛАЦИЈУ обавезно и
аутоматска провера бодовања. Користи **засебан тестни профил**, један таб на
`http://localhost:<тестни порт>`, без повезаног фајла за резерву. Не покретати
над профилом у коме неко учи. У конзоли учитати `tools/provera-bodovanja.js`:

1. `await proveraBodovanja()` — чува оба оригинална записа и освежава страницу.
2. Поново учитати скрипту, па `await proveraBodovanja2()` — извршава проверу,
   враћа оригинале и поново освежава страницу. Укључити „Preserve log”.
3. Поново учитати скрипту, па `await proveraBodovanjaPotvrdi()` — проверава
   стварно учитан профил и тек тада уклања резервни контекст.

После прекида: `await proveraBodovanjaVrati()`, па после освежавања трећи корак.
Ако потврда одбије опоравак, не брисати `provera.kontekst` нити затварати таб:
копија остаје у `sessionStorage` за поновни покушај/ручни опоравак. Потврда се

Питања и објашњења доступни су без мреже после успешне инсталације; слике се

Повратак старог кода објављује се са **новим, већим бројем**. Ако је стари кеш истог
броја непотпун, нови број омогућава нову припрему без преписивања активног кеша.
Ограничавање старих кешева је још отворен посао. `clients.matchAll()` не види
сваки документ који browser може вратити из BFCache-а; ни две провере нису
безбедна граница за брисање. [А5 одлука и будућа миграција](docs/superpowers/plans/2026-09-10-a5-zadrzavanje-starih-izdanja.md)
бележе стварни `pageshow.persisted` доказ и потребне провере пре чишћења.

## Умеци и плакат

`embed.html` — самостална страница са једним насумичним питањем, за уградњу на сајтове
ауто-школа (учитава `data.js` са јавне адресе). `plakat.html` — А4 плакат са QR кодом.

## Права

Питања, одговори и слике су из јавног сервиса еУправе (МУП Србије) и користе се
некомерцијално, за лично учење. Код апликације је ауторски рад власника

## Правила која су ушла у код 02.09.2026 (да не би била поново измишљана)

- **Типографска скала** — `--fs-xs/sm/md/lg` у `:root` су једине дозвољене величине текста
  (осим наслова и „украсних" бројева). Нова величина се НЕ уводи; бира се најближи токен.
  Уграђени (inline) `style="font-size…"` у `app.js` не сме да постоји — разреди су `.napomena`, `.tekstSm`,
  `.istaknuto`.
- **Боје** — свака боја која се користи по правилима је токен у `:root` (са тамним парњаком у
  `body.dark`). Голе хекс вредности смеју само: `#fff` на обојеној подлози и вредности које су
  саме „тамна варијанта" нечега.
- **Облик контроле прати последицу** — `.primary` једна главна радња по екрану, `.secondary`
  мења стање/покреће посао, `.danger` неповратно брише, веза (`.bcLink`, `<a>`) САМО за
  кретање или спољну адресу. Ниједна акција није нацртана као линк.
- **Заједнички цртач области** — `nacrtajOblasti(kontejner, {tacnost})` црта редове области
  и на почетној и у статистици (траке, бројачи, клик → списак, стрелица → акордеон подобласти).
  Ако се мења изглед реда, мења се на једном месту.
- **Одељци збирних картица** — у `tools/build-explanations.mjs` одељак се обележава
  `<div class="kSek" data-sub="138">…</div>`. Уз питање се приказују само одељци те
  подобласти (`suziKarticu`), уз дугме „Прикажи целу картицу"; у појмовнику се види цела.
  Више подобласти: `data-sub="138,141"`.
- **Распоред понављања** — тачан одговор помера распоред САМО кад је питање на реду
  (`dueOf(id) <= now`); тачан одговор пре рока је вежбање (`r.a++`, без `streak`/`due`);
  погрешан важи увек. Исто питање улази у дневне бројаче највише једном дневно.
  Тестови у `tools/provera-bodovanja.js` кодирају ова правила — кад се правило
  мења, мења се и тест, свесно.
- **Освежавање** — утврђено питање невидјено дуже од 21 дан (`OSVEZI_POSLE`) улази у
  `zaOsvezavanje()`; не дира `inQueue/dueOf`. Тачан одговор обнови датум, погрешан враћа у ред.
- **Текстови** — сваки `{ l, c }` пар се пише ручно; ћирилица не сме да садржи латинична
  слова осим: km/h, ЛАТ, GitHub, Enter, назива прегледача и чувара `#A/#B/@1/@2`.
  Чувари у тексту су `@1`, `@2` (никад `#` — оно се појављује дословно у „#број").

## Правила из пролаза испочетка (v97, 02.09.2026)

- **Један речник понављања** — „за понављање" је кровни појам (све у реду), „данас" и
  „касније" су његови делови (`ponDanas`/`ponKasnije`). Речи „спремно"/„чека" се више не
  користе. Објашњење правила (`queueTip`) стоји иза дугмета „?" (`pomocHtml` +
  `pomocTekstHtml` + `veziPomoc`) и отвара се на месту — никад само у облачићу.
- **Три стања у списку** — `✓` утврђено, `✗` погрешено (у реду), `◐` тачно из прве које чека
  једну потврду (`.qWait`). Тачан погодак никад не носи црвени знак.
- **Једна формула темпа** — `predlogTempa(dana, neodg)` (са резервом) храни и сажетак на
  почетној и „Предложи ми". Кад циљ постоји, сажетак не нуди други број; ако циљ не стиже до
  краја градива, каже то (`planPremalo`). Квота без градива је испуњена (`nemaNovih`/`nemaPon`).
  Одговор пре рока не пуни квоту понављања (`S.day.pon` само кад `!preRoka`).
- **Праг испита** — `PRAG_UDEO = 0.85`, `prag(total)`, `pragTekst(total)`; нигде више „84"
  уписано руком. Боја тачности: `accClass(acc)` (≥85 зелено, 70–84 жуто, <70 црвено) на
  свим местима. Предлог симулације: `SIM_PREDLOG_OD = 80` преко `readiness()` — исто
  правило цитирају водич и тура.
- **Датуми** — `fmtDatum(x, vreme)` → `dd.mm.gggg.`; датум последње провере базе је
  константа `BAZA_PROVERENA` (подножје + картица поверења).
- **Дугме не наслеђује величину картице** — `button { font-size: 1rem }`; `.primary`
  користи `--primaryBg/--primaryBgH` (не `--blue`, који у тамној теми посветли), трака на
  врху `--topbar`. Правило за `body.dark .primary` НЕ сме да се врати — оно је прегазило
  `--btnOff` и угашено дугме је изгледало упаљено.
- **Наслови група** — један разред `.grupaNaslov` (подешавања, појмовник, области у „Сва
  питања", подобласти у области). Размаци: `.opisRed`, `.razmakG`, `.card h3 ~ h3`; уграђени
  `style="margin…"` постоји још само у извештају симулације (намерно нетакнут).
- **Склопиве картице** — ЈЕДАН образац: `.pojBtn` + `sklopivo(btn, grupa, cilj)`; стрелица
  `▸/▾` долази из `aria-expanded`. Водич памти стање у `S.guide` слушачем ПОСЛЕ `sklopivo`.
- **Једно питање преко адресе** (`#/p/ID`) — `startList(..., { jedno: true, nazadLbl, hash })`:
  без бројача „1 од 1" и поља „Иди", назад води на почетну, „даље" покреће подобласт.
- **„Настави" на Сва питања** — `prviNeodgOd(S.seqPos)`: прво неодговорено од места где је
  стао, да план дана и области не би враћали на питање 1. На страни области „Настави" иде
  тачно од места (`contTipSec`) — два понашања, два текста.
- **Поновни приказ питања** — `prikazPitanja` (по `recordKey`) памти редослед понуда,
  избор и дат одговор при промени писма и, од v146, при враћању посете стрелицама
  прегледача. Обнова не бележи одговор поново. Дугмад за претходно/следеће питање
  у самом пролазу и даље покрећу нов покушај; то је различито од историје прегледача.
- **Дани до испита** — `danaDoIspita()` (round над две локалне поноћи); ниједан `ceil`.
- **Паукал** — `few(n)` + `novihPitanja(n)`: „1 ново питање / 3 нова питања / 5 нових питања";
  бројеви питања иду кроз `nQ(n)`. Реченицу која има број НЕ писати са придевом „ручно".

стара историја не добија измишљене изборе или поене по областима.

права на упис. Назад/Напред враћају локално отворена питања, старије покушаје
и фокус; не враћају снимак SIM-а. Без crypto провере остаје обичан локални
преглед и PNG дељење у радном табу. Сви прегледи аналитичком бројачу шаљу
заједничку путању `/#/pregled`, никада отисак личног покушаја.

## Темпо који рачуна стварност (v112, 04.09.2026 — тура 1)

Милан: „можда и јесте препрека за испит, треба да се напомене, да се темпо мења… и ако одрадимо
више од дневног циља да и то уђе у рачуницу".

- **Ауто режим (`S.plan.auto`)** — дневна квота се изводи из онога што је ОСТАЛО и броја дана до
  испита, сваког дана изнова: `cNovih = ceil(neodgovorenih / danaZaNovo)`,
  `cPon = min(120, max(20, cNovih + ceil(наРеду / dana)))`. Зато вишак урађен данас САМ снижава
  сутрашњу квоту — не памти се никакав дуг. Без датума испита ауто нема од чега да рачуна и то каже.
- **Пресуда уместо утехе.** Три гране, свака са бројевима, све три доња граница (не прогноза):
  · **стижеш** — градиво и понављања стају у преостале дане;
  · **градиво да, понављања не** — колико питања ће се видети само једном;
  · **не стижеш градиво** — „то ЈЕСТЕ препрека", са бројем питања која остају невиђена.
  Рачун: `otvoriS = min(neodg, cNovih × dana)`, `potrebnoPon = наРеду + otvoriS`,
  `kapacitetPon = cPon × dana`. Свако ново питање улази у ред (`inQueue`) и тражи бар једну потврду —
  отуда сабирак.
- **Лостови су дугмад са бројем**, не савети: „Подигни на N нових и M понављања" и
  „Учи прво оно што се на испиту и појављује".
- **Приоритет по тежини на испиту (`S.plan.prio`)** — нова питања иду редом по `tezinaPodoblasti()`,
  изведеној из званичног шаблона `SIM_SLOTS` (слот са више подобласти дели јединицу на њих:
  претицање 134 носи 5, брзине 135 три, подобласт 91 нула). Ко нема времена за све, изостави
  оно што се ретко и појави, а не оно докле се стигло по редоследу базе.
- **Вишак се види:** „данас си урадио 90 нових, а циљ је 65 — 25 преко циља" (+ у ауто режиму
  „сутрашња квота ће зато бити мања").
- Провере: 45 ставки (девет нових за темпо и приоритет). Датум у тестовима мора да буде ЛОКАЛНИ
  (као `localDay()`), не `toISOString()` — иначе `S.day` не важи за данас и квоте испадну нула.

## Шанса да положиш и правило о симулацијама (v113, 04.09.2026 — тура 2)

Милан: „колико симулација би требало да прођемо, и колико да положимо да бисмо имали
самопоуздање да заправо знамо и полажемо константно?"

- **Тачан рачун унутар условног модела.** `sansaZaProlaz(slotovi)` рачуна расподелу ЗБИРА поена динамичким
  програмирањем преко 99 могућих поена (41 слот × 99 корака), па враћа `P(zbir ≥ prag)`.
  Маргинале су тачне — вероватноћа слота је просек `pOf` по скупу питања која у њега могу —
  а претпоставка је независност слотова, што стоји у самом објашњењу на екрану.
  Пример који показује зашто ово вреди: очекиван резултат 80/98 („пао") даје шансу од 27%,
  дакле ни близу онога што „80 поена" сугерише.
- **Правило од четири ставке (`spremnost()`)**, свака са бројем и ✓/✗:
  бар 5 симулација · рађене бар 3 различита дана · последње 3 положене са бар 5 поена преко
  прага · процена бар 85%. Разлог зашто ниједна сама није довољна стоји у тексту: при стварној
  шанси од 70% три положене заредом дешавају се у трећини случајева.
- Приказ: Статистика носи и очекиван резултат и шансу и списак од четири ставке; дугме „Испит"
